# سلاح الفرعون — AI Tutor

مدرس خصوصي تفاعلي بالذكاء الاصطناعي يبني تجربة تعليمية شخصية لكل طالب، يبدأ من المناهج المصرية والسعودية ومصمم للتوسع إلى بقية الدول العربية.

> **انظر `PROJECT_BIBLE.md` أولًا** — هو الذاكرة الدائمة للمشروع (القرارات، العمارة، الحالة).

---

## المتطلبات

- Node.js >= 20 (طُوّر على v24)
- Git
- Windows/Linux/macOS — **لا يحتاج** Docker ولا PostgreSQL ولا مفاتيح AI للمعاينة (Mock provider افتراضي).

## التشغيل السريع (للمطوّر)

```bash
npm install

# 1) إعداد المتغيرات
cp .env.example .env        # ثم عدّل SESSION_SECRET فقط (للمعاينة يعمل بالافتراضي)

# 2) زرع بيانات المنهج (منهجان نموذجيان: مصر + السعودية)
npm run db:seed

# 3) تشغيل كل شيء (server :3001 + web :5173)
npm run dev
```

> البذر **متعدد الدول** (PHASE 16): «مصر» (الأصل) و«السعودية» — دولة/نظام/صف/منهج/دروس بمحتويات RAG نموذجية لكل بلد، والكتالوج العالمي للمواد مشترك؛ البذر idempotent (إعادة التشغيل بلا أثر). أي بلد جديد = بصمة `CountrySeedSpec` إضافية في `server/src/db/seed.ts`.

افتح http://localhost:5173 → سجّل حسابًا → اختر: مصر **أو السعودية** → الصف السادس → الرياضيات → درس → ابدأ المذاكرة.

> السيرفر يطبّق migrations تلقائيًا عند الإقلاع. قاعدة البيانات تُخزن في `server/data/alfarouq.sqlite`.

## اختبارات المتصفح (Playwright E2E)

اختبارات حقيقية عبر Chromium تمر المسار الكامل: **Browser → React → Vite proxy → Fastify → SQLite → RAG → AI provider → DB → Browser**. لا يستخدمون أي Mock للـAPI، والمزوّد الافتراضي هو Development Provider المدمج (`mock`).

```bash
npm run e2e:install   # مرة واحدة فقط
npm run e2e           # يُشغّل كل شيء تلقائيًا
```

- **عزل تام للبيانات**: اختبارات Playwright تشغّل خادمها الخاص على منفذ **3107** بقاعدة SQLite مؤقتة تُزرع من جديد عند كل تشغيل — لا تُمسّ بيانات التطوير أبدًا. واجهة الويب تُختبر على المنفذ القياسي **5173** وبروكسيتها تُوجّه لخادم الاختبار (المتغير `VITE_API_PROXY_TARGET`).
- **حسابات تجريبية** (تُزرع في كل قاعدة اختبار): طالب `student@alfarouq.test` / `student-demo-123` — Admin `admin@alfarouq.test` / `admin-demo-123` — **ولي أمر `parent@alfarouq.test` / `parent-demo-123`** (مربوط مسبقًا بالطالب التجريبي؛ كود الربط `SLH7KQ9M`).
- **المتطلبات**: منفذا 3107 و5173 حرّان (اختبار Playwright يرفض ميناءً مشغولًا حتى لا يلمس بيئة التطوير). التفاصيل والقيود في `TEST_PLAN.md` §5–8.

## Vision Upload (سؤال مصور)

في غرفة الدردشة زرّ **«📷 صورة سؤال»**: يلتقط الطالب صورة لسؤاله المطبوع/المكتوب ويرفقها مع رسالته (أو بدون نص). الخادم يخزّنها (SQLite BLOB) ويمرّرها للمُدرّس متعدد الوسائط (Gemini `inlineData` في الإنتاج، المزوّد `mock` يقرّ قراءتها في التطوير) مع بقاء التوجيه عبر RAG. الحدود: صيغ PNG/JPEG/WebP وبحد `MAX_IMAGE_KB` (افتراضي 5000). التفاصيل والقرارات في `DECISIONS.md` D-014.

## Voice conversation (سؤال بصوت)

طبقة صوتية كاملة في المتصفح عبر **Web Speech APIs** (بلا مفاتيح وبلا تغيير في الخادم):
- **سؤال بصوتك**: زر **«🎙️ سؤال بصوت»** يستمع بالعربية (`ar-EG`)، وينقل النص الناتج إلى حقل الرسالة **للمراجعة والتعديل** ثم ترسله كالمعتاد. يعمل في Chrome/Edge على localhost أو HTTPS؛ رسالة واضحة عند غياب دعم المتصفح، وأخطاء عربية موضحة (رفض الميكروفون، «لم نسمع صوتًا»، الشبكة…).
- **سماع الرد**: يُنطق رد المدرس تلقائيًا بعد سؤال صوتي، ويمكن سماع أي رد سابق بزر **«🔊 استمع»** في فقاعته، مع **«⏹ إيقاف»** في شارة «جارٍ الاستماع إلى رد المدرس…» (صوت عربي إن وُجد).

الدردشة النصية وVision يعملان كما هما — الصوت لا يغيّر عقود الـAPI. أتمتة E2E (A1–A3) تحقن `SpeechRecognition`/`speechSynthesis` حتمية في المتصفح (لا يمكن أتمتة ميكروفون حقيقي). التفاصيل والقرارات في `DECISIONS.md` D-015.

## Document upload (ملف سؤال في الدردشة)

في غرفة الدردشة زرّ **«📄 إرفاق ملف»**: يرفق الطالب سؤالًا مكتوبًا بملف (**PDF / DOCX / TXT / MD**) مع رسالته أو بدون نص. الخادم يستخرج نصًا محدودًا (`MAX_DOCUMENT_CHARS`، افتراضي 20000 حرف) بمحللات JS نقية (PDF عبر `pdfjs-dist`، DOCX عبر `mammoth`) ويُمرّره للمُدرّس **كمدخل مستند — لا يُلصق في تعليمات النظام أبدًا**، مع بقاء التوجيه عبر RAG واسترجاع احتياطي للملف بلا نص. **فحص توقيع (MAGIC bytes)** يرفض قبل الاستخراج أي ملف لا يطابق نوعه المعلن (`FILE_TYPE_MISMATCH` — نص مُعاد تسميته `.pdf`). الحدود: `MAX_FILE_KB` (افتراضي 10000)، وملف ممسوح ضوئيًا بلا نص قابل للاستخراج → **قراءة تلقائية بالـOCR** (مزوّد AI عبر `AI_OCR_PROVIDER`: mock افتراضيًا، Gemini في الإنتاج؛ `MAX_OCR_CHARS` افتراضي 20000) تُخزَّن في `messageAttachments.ocrApplied` وتظهر شارة «نص ممسوح ضوئيًا — قُرئ تلقائيًا» (تتمايز بالنص بالـocr المطبوع). أمنيًا: **إعادة فحص الحقن على نص الملف خادميًا قبل أي استدعاء نموذج** ترفض أي محاولة تجاوز تعليمات برسالة «أنا هنا لمساعدتك في درسنا فقط». التفاصيل والقرارات في `DECISIONS.md` D-016 وD-019 وD-023.

## Curriculum file import (ملفات المناهج في قاعدة المعرفة)

للمسؤول (admin) نقطة استيراد مخصصة **`POST /api/admin/documents/ingest-file`** ترفع ملف **PDF / DOCX / TXT / MD** كـ`dataUrl` (base64) مع نطاق الدرس الإلزامي (`scope`). الخادم يستخرج النص (نفس المحللات الآمنة: `pdfjs-dist` + `mammoth`) ويخزّن **البايتات الخام + sha256** على النسخة، ثم يمضي في أنابيب chunking/embedding نفسها — فيُسترجَع المحتوى داخل درس محدّد فقط (عزل بين الدروس) ويصبح **محتوى `<context>` لا تعليمات**. **فحص توقيع (MAGIC bytes)** يرفض قبل الاستخراج أي انتحال لصيغة (نص→PDF، ZIP عام→DOCX، PDF→نص — `FILE_TYPE_MISMATCH`). الحدود: `MAX_CURRICULUM_FILE_KB` (افتراضي 20480 = 20MB) و`MAX_CURRICULUM_DOCUMENT_CHARS` (200000)؛ تكرار نفس الملف لنفس المنهج → `409 DOCUMENT_ALREADY_INGESTED`؛ استخراج صفري (ممسوح ضوئيًا PDF/DOCX) → **إنقاذ بالـOCR** (نص < 40 حرفًا + MIME مؤهّل → قراءة تلقائية قبل `ingestFile`؛ يبقى TXT قصير صادق `400 EMPTY_DOCUMENT`)؛ فشل مزوّد الـOCR → هبوط آمن إلى `EMPTY_DOCUMENT` (لا انهيار). التفاصيل والقرارات في `DECISIONS.md` D-017/D-019/D-023 و`API_SPEC.md` §4/§7.

## Admin dashboard (لوحة الإدارة)

يكمل الاستيراد بواجهة استخدام فعلية (PHASE 14): عند الدخول بحساب `admin` يظهر في الرئيسية زرّ **«لوحة الإدارة»** (لا يظهر للطلاب) يفتح شاشة فيها:
- **استيراد ملف نهجي**: اختيار الملف (PDF/DOCX/TXT/MD) + عنوان/مصدر اختياريان + اختيار **نطاق الدرس** بنفس سلسلة قوائم المنهج (دولة→نظام→صف→مادة→منهج→فصل→وحدة→درس) → رفع مباشر عبر `ingest-file` مع عرض نجاح بعدد المقاطع أو رسالة خطأ واضحة (مثل «مستورد مسبقًا»).
- **قائمة المستندات المستوردة**: عنوان/نوع/اسم الدرس/عدد المقاطع/التاريخ — تغذيها `GET /api/admin/documents` (تُربي الآن بمعلومات الدرس والمقاطع).
- **إحصاءات سريعة (PHASE 17)**: بطاقات لحظية أعلى اللوحة (مستخدمون/طلاب/جلسات/رسائل/مستندات/مقاطع/مناهج/دروس) من `GET /api/admin/stats` — تجميع صافٍ بلا جداول جديدة، وطلل الجلب لا يعطّل الاستيراد.
- **الاشتراكات + الوفورات (PHASE 27)**: بطاقتا «الاشتراكات — نظرة سريعة» (الخطة المخزّنة + **السارية فعليًا** + معدل التحويل) و«الذكاء الاصطناعي — الاستخدام والوفورات» (نداءات/توكن/تكلفة فعلية/إصابة كاش/وفورات توكن و$ تقديرية) — من نفس `GET /api/admin/stats`؛ عدّادات فقط بلا محتوى رسائل.
- **أسئلة مولّدة بالمفهوم (PHASE 28)**: لا مفهوم بلا مادة — عملة LLM جديدة **`question_gen`** (قابلة للتخزين المؤقّت، mock حتمي أوفلاين) تولّد **سؤال MCQ واحدًا لكل مفهوم بلا أسئلة** مرتكزًا على مقاطع الدرس (الإجابة الصحيحة نص حرفي من الدرس، وبدون التقاط جُمل النفي التربوي). الطالب يجد في خطته «توليد سؤال» للمفاهيم المكتشفة حديثًا (`tracked:false` المدرجة بعد المتتبعة) ويمارس فورًا، والمدير يقسّم البنك دفعة واحدة (`admin-gen-questions`) بتقرير idempotent بلا تسريب للمفتاح — فيغلق آخر «مؤجل» من حلقة الضعف→ممارسة→إتقان أوفلاين.

التفاصيل والقرارات في `DECISIONS.md` D-018/D-021/D-031.

## Parent dashboard (لوحة أولياء الأمور)

لولي الأمر (دور جديد قابل للتسجيل باختيار **«ولي أمر»** في نموذج التسجيل) شاشة كاملة تفتح من الرئيسية (PHASE 18):
- **ربط الابن بكود قصير**: يعرض الطالب في صفحته الرئيسية بطاقة **«كود ولي الأمر»** (رمز مشاركة فريد مولّد تلقائيًا، 8 محارف بلا محارف ملتبسة)؛ ينسخه الوالد في نموذج الربط ← `POST /api/parent/link` (أخطاء واضحة: «رمز الربط غير صحيح»، «هذا الطالب مربوط بالفعل»).
- **قائمة الأبناء**: بطاقات باسم/صف/منهج + عدد الجلسات وآخرها — وتفاصيل كل طفل: هوية تعليمية، **تقدم (مفاهيم + نقاط قوة/ضعف)**، و**ملخصات الجلسات** (الدرس/التاريخ/الحالة بعدّادات الرسائل فقط).
- **تفاصيل الجلسة (PHASE 23)**: زر «التفاصيل» في أي جلسة ← **خط زمني بيانات وصفية فقط** — لكل دورة (دور/نوع/وقت/شارات مرفق: صورة/مستند/OCR)، **مفاهيم عُرضت** في الجلسة، المدة، و**تنبيه سلامة** عند وجود أعلام حقن (المحاولات المحجوبة تظهر كمؤشرات لا كنصوص).
- **ملخص الجلسة الآمن (PHASE 29)**: زر «عرض الملخص» في تفاصيل أي جلسة ← **نفس البطاقة التي يراها الطالب** (عنوان/تركيز/عدّادات/نقاط قوة/اقتراحات) — مبنيّة من **بيانات وصفية فقط** (`recap` يُحسب عند الطلب، بلا محتوى رسائل في الاستدعاء أو النتيجة) مع حارس «لا نص حرفي» وسقوط آمن حتمي.
- **العزل والأمان**: كل قراءة تشترط صراحةً رابط الوالد↔الطفل (طفل أجنبي → 404 بلا مؤشر وجود)؛ **لا يُكشف محتوى رسائل خام إطلاقًا** — حتى في تفاصيل الجلسة لا يُحدَّد عمود `content` من قاعدة البيانات بنيويًا (خط زمني فوق-بيانات فقط)؛ إلغاء الربط متاح في التفاصيل.
- الحساب التجريبي أعلاه (`parent@alfarouq.test` / `parent-demo-123`) مربوط بالطالب التجريبي مسبقًا.

التفاصيل والقرارات في `DECISIONS.md` D-022 + D-027 + D-033 و`API_SPEC.md` §8.

## Subscriptions + Achievements (الفوترة بلا بوابة دفع + الإنجازات)

خطة اشتراك MVP **بلا بوابة دفع** (PHASE 20) تُدار من لوحة الإدارة مباشرة:
- **الخطط**: كل طالب يبدأ بصف اشتراك **كسول** مجاني/تجريبي؛ «الخطة المميزة» تُمنح عبر **`PUT /api/admin/subscriptions/students/:id`** (سجل تدقيق `subscription.update`). الخطة المميزة فعّالة فقط وهي `trialing|active` وغير منتهية — المنتهية/`past_due`/`cancelled` تهبط تلقائيًا لحدود المجاني.
- **الحدّ اليومي**: المجاني `DAILY_MESSAGE_LIMIT` (50) والمميز `PREMIUM_DAILY_MESSAGE_LIMIT` (افتراضي 0 = **بلا حدود**) — يُفرض خادميًا في محرك المدرّس ويظهر في بطاقة «خطتك» بالرئيسية («مجانية»/«مميزة» + انتهاء + حد اليوم).
- **الإنجازات (6 شارات)**: تُمنح تلقائيًا خادميًا على أحداث دورة الحياة — «أول خطوة» (أول جلسة)، «مستكشف» (5)، «عالِم صغير» (10)، «بارع الحوار» (50 رسالة)، «قارئ نهم» (أول ملف)، «مصوّر الأسئلة» (أول صورة) — بمنح **مضاد للتكرار** وبأفضل جهد لا يكسر الجلسة، وتُعرض في شاشة «🏆 إنجازاتي». التفاصيل والقرارات في `DECISIONS.md` D-024 و`API_SPEC.md` §9.

## RAG infrastructure (مزوّد المتجهات + إعادة التصنيف عبر النموذج)

خط RAG يعتمد واجهتين مجردتين منذ PHASE 5 — PHASE 21 جعلتهما **مزوّدَين** بالاختيار من الإعداد (نفس نمط مزوّدي AI: الافتراضي محلي/حتمي، الخارجي اختياري):
- **مخزن المتجهات**: `VECTOR_STORE=sqlite|qdrant` — `sqlite` (الافتراضي، بلا اعتماديات) يخزّن في `rag_vectors`؛ `qdrant` (HTTP صافٍ، Docker أو Qdrant Cloud) عبر `QDRANT_URL`/`QDRANT_COLLECTION`/`QDRANT_DIMENSION` مع point id حتمي وعزل النطاق على الـpayload. **فشل غير متماثل**: الاستيراد الإداري يعلن `503 VECTOR_STORE_UNAVAILABLE`، أما الاسترجاع فيهبط آمنًا إلى `[]` — جلسة الطالب لا تنهار أبدًا.
- **إعادة التصنيف**: `RAG_RERANKER=lexical|model` — المعجمي سريع وحتمي (الافتراضي)؛ `model` يسأل النموذج (عملية `rerank`) ترتيبَ المقاطع بـJSON صارم مع **هبوط آمن** لأي فشل؛ `RAG_ENABLE_RERANK=false` يعطّلها تمامًا. عقد `upsert` يمرّر النطاق للخارجية لحفظ العزل. التفاصيل في `DECISIONS.md` D-025 و`RAG_SYSTEM.md`.

## AI caching (التخزين المؤقت — PHASE 22)

العمليات **الحتمية** تُخدم من ذاكرة LRU داخل العملية (جاهزة منذ PHASE 6، فُعِّلت في PHASE 22) — كل ضربة = صفر استدعاء مزوّد حقيقي = صفر تكلفة:
- **تُخزَّن**: مصنّف النوايا + إعادة التصنيف (`complete`)، المتجهات (`embed` — نفس النصوص → نفس المتجهات، ساعة)، وOCR (`ocr` — نفس البايتات → نفس النص، 24 ساعة؛ طالبان يرفقان الملف الممسوح نفسه في نفس العملية → الأول يدفع فقط).
- **لا تُخزَّن أبدًا**: ردود المعلّم/الملخص/المراجعة — ديناميكية لكل طالب وجولة.
- **الفاتورة تعكس الاستدعاءات الحقيقية**: ضربة الـcache بلا صف في `ai_usage_logs`؛ `AI_CACHE_ENABLED=false` يُرجع كل شيء للمزوّد مع التسجيل. العدّادات على `GET /api/health` → `cache: {hits, misses, size, maxEntries}`. التفاصيل في `DECISIONS.md` D-026.

## Concept mastery + Practice (محرك الإتقان والتمرين — PHASE 24)

المنصة تعرف **ماذا يتقن الطالب ومتى ينحسر** — وتمنحه قناة تمرين فعلية تغذّي التقييم تلقائيًا:
- **مستويات إتقان عربية رباعية** (متقن ≥0.8 / متقدم ≥0.6 / قيد التقدم ≥0.4 / يحتاج مراجعة <0.4) تُحسب **قراءةً** من سجلات التقدم والتقييمات بمحرك نقي (`progress/mastery.ts`) — بلا عمليات كتابة جديدة.
- **انحلال النسيان**: منحنى **Ebbinghaus أُسي** (`MASTERY_DECAY_PER_DAY`، افتراضي 0.02 ≈ نصف عمر 35 يومًا) يظهر في لوحة الطالب (نسبة الانحلال + أيام منذ آخر ممارسة + سهم اتجاه صعود/ثبات/هبوط) ولوحة ولي الأمر (شارات المستوى في تقدم الطفل) — **قراءةً فقط**؛ ذاكرة المعلّم طويلة المدى تحتفظ بالقيمة الخام.
- **التمرين السريع**: زر «تمرين على نقاط ضعفك» في الرئيسية ← سؤال MCQ حتمي (بلا أي استدعاء AI — تصحيح محلي فوري، أوفلاين وبلا تكلفة) من **أضعف المفهوم المتتبع أولًا** ثم أي سؤال ضمن مناهج الطالب المسجَّلة. كل إجابة تكتب `answers` + **تقييمًا** (`recordAssessment`) فتحدّث مستويات الإتقان لحظيًا مع شرح.
- **خطة ممارستك (PHASE 25)**: الإتقان يتحول إلى **خطة مرتّبة قابلة للتنفيذ** — كل مفهوم متتبَّع يظهر بترتيب «الأضعف أولًا» (انحلال ثم إهمال ثم معرّف) مع درسه وعدد الأسئلة المتاحة، وزر **«تمرّن الآن»** يفتح التمرين مقيّدًا بالمفهوم مباشرة؛ الخطة قراءة نقيّة تُحدَّث بعد كل إجابة، وعدّاد الأسئلة يحترم مناهج الطالب المسجَّلة (غير المسجَّل في منهج = بلا أسئلة — لا وعود بلا مادة).
- **معادلة مستجيبة للصعوبة (PHASE 26)**: دلتا الإتقان تستجيب لصعوبة السؤال — سهل +0.15/−0.1 (الحسم التاريخية)، متوسط +0.175/−0.125، صعب +0.2/−0.15؛ المحاولة الأولى محايدة (0.6/0.1) فالتفاضل على التتابع، وفحوص الدرس بلا صعوبة تبقى كما كانت تمامًا.
- **شارات يغذّيها المحرك (PHASE 26)**: أول إجابة تمرين تجلب **«انطلاقة التمرين»**، وأول مفهوم عند مستوى «متقن» (بالدرجة المعروضة بعد الانحلال) يجلب **«أول إتقان»** — تظهر في شاشة 🏆 إنجازاتي المعتمدة (8 شارات) بلا أي تغيير ويب؛ الحقن best-effort لا يكسر حلقة الإجابة أبدًا.
- **بلا تسريب للمفتاح**: `correctIndex`/`answerKey` لا يغادران الخادم أبدًا — الاستجابة تعرض نص الخيارات فقط؛ السعودية بلا أسئلة تجريبية عمدًا (إثبات نطاق التمرين لكل منهج). العزل: غير مسجَّل في منهج السؤال → 404، ولي أمر → 403، خيار غير صالح → 400.
- التفاصيل والقرارات في `DECISIONS.md` D-028 + D-029 + D-030 و`API_SPEC.md` §10.

## ملخص الجلسة الآمن (PHASE 29 — إغلاق D-027)

المدرّس لا ينهي درسًا بلا محصّلة: بعد أي جلسة يحمل صفّها في **«جلساتي السابقة»** زر **«ملخص الجلسة»** يفتح بطاقة تلخّص **ماذا فعلنا** (عنوان، تركيز، كم سؤال/ردّ، المدة، المرفقات، نقاط قوة واقتراحات) — وولي الأمر يرى **نفس البطاقة** من لوحته. البطاقة **آمنة بالتصميم** لا بالوعد: عملية LLM `recap` لا تتلقى سوى **بيانات وصفية** (عناوين الدروس/المفاهيم + عدادات) — نصوص المحادثة لا تدخل الوعد ولا النتيجة؛ حارس «لا نص حرفي» يرفض أي ناتج يعيد إنتاج رسالة ويسقط إلى ملخص بنائي حتمي آمن (`fallback:true`). جلسة بلا محادثة → رسالة «لا توجد محادثة». التفاصيل والقرارات في `DECISIONS.md` D-033 و`API_SPEC.md` §3/§8.
