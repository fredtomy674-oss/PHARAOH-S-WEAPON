## 2026-10-16
- PHASE 146 — Fatal grading fix: the tutor said «صحيح» to a wrong WRITTEN answer. Root cause: `lastAnswerCorrect` was only ever computed for the number-line widget, so every written answer's verdict was the model's opinion — and the prompt explicitly told it to judge («صحيحة → امدحه»). Mirroring the widget design, a `question` reply-part may now carry a server-only `answer` key (stored in the new `messages.question_answer`, migration `0014_sturdy_namor`, stripped from every wire view by `withoutQuestionAnswer`), and `server/src/modules/tutor/questionKey.ts` grades the student's text deterministically (`gradeTextAnswer`: ordered number run so «2/3» ≠ «3/2» and 7 ≠ 17; word coverage ≥ 0.7 with the Arabic article folded). The prompt is told the verdict and forbidden from inventing one; with no key it forbids praise outright, and `assertsCorrectness` + `unverifiedAnswerFallback` guarantee no unearned «أحسنت» ships. Also fixed the intent classifier: confusion is now decided before «فهمت», the acknowledgement patterns are anchored (the old unanchored `/واضح/` read «مش واضح» as «understood») and the JS `\b` that never matched Arabic is gone. Server typecheck/lint PASS, 105 files / 952 tests PASS.

## 2026-10-16
- PHASE 148 — Comprehensive avatar "life" layer: the avatar no longer only blinks and sways. New `web/src/avatar/lifeLayer.ts` is a purely functional, deterministic motion layer (same instant ⇒ same pose, so it unit-tests in node) that is *additive on the explicit state* — it never invents a mood, and silence stays silence. Each frame it layers breathing (~3.8 s, chest/shoulders), body sway (~5.2 s) and a slow weight shift (~9 s, hips/spine); head/neck/eye micro-life from bounded deterministic noise with independent per-axis seeds plus a small gaze drift on the eye bones; and per-state gestures (a nod for correct, a soft tilt for partial, a gentle head shake for incorrect, an occasional attentiveness nod while listening, a light hand beat while speaking — only on the known Z axis, never the unverified elbow axis). Transitions are exponential per-bone pursuit, frame-rate independent, with no keyframe system. `createLifeAnimator` writes normalized humanoid bones only, which `vrm.update(dt)` maps onto the raw skeleton — replacing the one-shot `relaxBindPose` (now deleted). Reduced motion means *exactly* the held pose for the state (no breathing/sway/gaze/gesture/blink), with `vrm.update(0)` plus `springBoneManager.reset()` so the hair physics stops instead of being caught mid-swing, while the mouth still follows the real audio envelope (the expression path is separate). Two real bugs surfaced by the live render check: (1) the VRM expression manager **latches** — `happy` from a correct answer stayed painted on the face into every later state; the renderer now writes *every* preset every frame (`EXPRESSION_PRESETS`, zero when unused), the same class of bug as the earlier blink latch; and (2) freezing the springs at an arbitrary mid-swing state left the hair mismatched to the head, fixed by `reset()`. Tests: new `lifeLayer.test.ts` (14 cases) and a new `visemeMapper.test.ts` case asserting the preset list covers every state's needs. Live Playwright+swiftshader verification: idle motion is real (10.7% of pixels change between frames), correct shows joy plus a nod, and reduced motion is **bit-identical** between frames (0 differing pixels). Web typecheck/lint PASS, 33/33 web tests PASS. Still lab-only — not yet wired into the lesson room.
